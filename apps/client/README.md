# Viyu client

React/TanStack UI shared by the standalone Go server, Wails 3 desktop client and Capacitor Android client.

From the repository root, enter `nix develop` and run `task dev` for Go/PocketBase plus Vite hot reload. `task desktop:run` builds the UI and launches the native application instead. See the root README for data-directory and runtime requirements.

Web requests use the current origin. Native clients first ask for an external Viyu server, validate `/api/health`, persist that choice and use server-scoped PocketBase auth storage. `lib/server.ts` owns setup and changing instances; `lib/pocketbase.ts` centralizes the selected API origin. `lib/server-url.ts` (pure, tested) validates the server address: a path prefix (`https://host/viyu`) is kept and every request is built relative to the base (`apiUrl`). The session travels as an `Authorization: Bearer` header only (no cookie, `credentials: 'omit'`): hls.js adds it to the stream requests, and live chat reads its SSE through `fetch` and a stream reader (`lib/sse.ts`, a tested incremental parser) because `EventSource` cannot send headers. `lib/session.ts` ends the session on any 401 (token and resume positions cleared, back to `/login`) and renews the token at boot, every twelve hours and when the window regains focus near its expiry. A share link is built from the server base, not from the shell's own origin.

`task build:ui` type-checks and builds the frontend, then copies production assets into `apps/server/internal/ui/dist` for embedding. `task build:ui:desktop` builds the desktop shell UI (`VITE_CLIENT_TARGET=desktop`, which shows the server-setup screen) into `apps/desktop/dist`. `task type-check` runs the client compiler without a production bundle. Android synchronizes the same `apps/client/dist` with Capacitor.

Frontend record and API types belong to `src/types` and are imported through `@/types`; there is no separate types workspace. Navigation, forms, loading/empty states and responsive media grids share UI primitives (`Dialog`/`ConfirmDialog` are the only modals, `MediaGrid` the base of every video list, `useAbortableEffect` the one request-lifecycle hook). Video cards use one-line ellipsized titles with full-title tooltips and one channel line, format view counts compactly with exact-count tooltips, and show relative publication dates with the full date on hover. A video has one `published` value: `YYYY-MM-DD` when only the day is known, a full RFC3339 UTC timestamp when the exact time is known, empty when unknown (`features/video/utils/publication.ts` converts the `videos` record's PocketBase date, whose time at exactly midnight UTC means "day only", and orders publications by instant). Today's publications use hours or minutes only when the exact time is known. A date skeleton remains visible while missing metadata is loading. Feed, channel and subscription views sort known dates newest first, with unknown dates last; history retains its viewing order and labels viewing time separately. Unknown publication dates stay absent. Missing channel artwork is enriched from channel metadata, and search results support direct subscription.

Data layer: every PocketBase-backed collection (`src/collections`, `features/video/collections`) is a TanStack DB collection in `syncMode: 'on-demand'` (settings, one row per user, is the only eager one): live queries compile their `where`/`orderBy`/`limit` into PocketBase filters, so `videos` and `channels` are never loaded whole. Lists page with `useLiveInfiniteQuery` and load the next page from `VirtualGrid`'s end-reached callback; single records are point lookups by id; subscriptions are one shared query (`SubscriptionsProvider`, indexed by channel) instead of one per card. Writes go through `collection.insert/update/delete` with ids from `collection.utils.newId()` (`lib/watch-history.ts`, `lib/reactions.ts`, settings, profiles); the only direct request to a collection endpoint is the final keepalive playback save.

`PlatformBadge` identifies video and channel cards at the bottom right, below video card actions, and adds named logos to quick-search rows and source selectors. `ChannelCard` (search results) embeds a subscribe/unsubscribe button (`useChannelSubscription`, same as quick-search rows and the channel page) positioned over the card beside its link — never inside it, so toggling never navigates; it reflects the active profile's state with a pending spinner and destructive styling on failure. `PlatformFilters` filters loaded mixed-platform search and video grids without changing session context or issuing a new query. Filters stay available when watched-video preferences hide the selected platform's videos; a selection no longer present in the data falls back to All. The home feed has the platform filter over the videos it has loaded; it is not the source pills, which choose between the local feed and a connected source's own feed. A platform chip only shows while at least two platforms remain in the loaded videos.

Sources has its own primary navigation route. The feed offers source pills as soon as a source is connected; All combines local recommendations with connected home feeds, while each source remains individually selectable. YouTube and Twitch connections use manual Netscape-cookie import on the selected server; native clients do not run a local browser-login helper. Twitch public search, channel catalogs and public VOD playback require no account or cookie import. An optional Twitch connection uses `auth-token` for followed live channels and account-authorized playback. Source credentials are submitted only to the selected Viyu server. Media requests authenticate with the same Bearer header as the API, so no token ever appears in a URL. Connected-source content has a record like any other, so it is opened through `/player/<id>` and `/channel/<id>` with the source in navigation state (`viyuSource`), which only selects the private way of reading it (`?source=` on the API calls), and public or connected Twitch metadata, channels and streams are never routed to YouTube extractors.

Each source card has an **Enabled** switch, separate from its connection badge. `SourcesProvider` exposes `isEnabled` and `setEnabled`; `lib/source-activation.ts` holds the pure rules: nothing is hidden while the source list is loading or failed, only a platform the server reports as off hides content. A source is a connected feed only when it is both connected and enabled. Subscriptions, history, likes, series and notifications of a disabled platform are filtered client-side because they are read from PocketBase collections, and a stale connected-source selection or search platform on a disabled source falls back to Viyu or All.

The player has one **Comments** section for every platform, chosen by `video.comments` (`list` renders `VideoComments`, `chat` renders `VideoChat`, absent hides it), never by the platform name; a live chat still opens by itself. `lib/platforms.ts` is the one place that knows how a platform looks (name, icon, tone, description key); an unknown platform gets a neutral icon, its id and the server's own description. A card shows connection controls only when the platform's `connectionMethods` include `cookies` (PeerTube has none). PeerTube ids (`host:uuid`, `name@host`) are percent-encoded everywhere and round-trip through the router, which `tests/id-routing.test.ts` checks.

Feeds and search load subsequent pages automatically near the end, with skeletons while the request is pending and retry controls on failure. A connected source's home-feed error is silent in All and shown in a retryable snackbar when that source is selected. The selected source travels in browser history state rather than URL query parameters, including during connected playback; a copied URL opens without that session context. Channel links open public catalogs; available connected sources are used when playing their videos. Playback settings can hide videos marked watched in the active Viyu profile from discovery and search, without hiding history or likes. This does not import YouTube's full watch history.

Links are built by `lib/links.tsx` (`VideoLink`, `ChannelLink`, `useOpenVideo`, `useOpenChannel`, `useOpenLink`, with the target choice in the pure `lib/link-targets.ts`): the `id` of a video or channel is its record id, so a video goes to `/player/<id>`, a stream in progress to `/live/<channel id>` and a channel to `/channel/<id>`; a pasted video link goes through `POST /api/resolve` (`api.resolveVideo`) and then opens the returned video. `lib/records.ts` looks a record up in PocketBase for `RecordPlayer` and `ChannelScreen`; the platform's own id it also returns is only used for what talks to third parties directly (SponsorBlock, Return YouTube Dislike, YouTube storyboard previews) and for a Twitch stream's chat login. History rows and reactions are identified by their `video` relation only (`(profile, video)` is unique on the server; `lib/watch-history.ts`, `lib/reactions.ts`); their platform and channel are those of the expanded video. The navigation state `viyuSearchPlatform` only carries the search page's platform filter.

The Subscriptions videos tab reads the `videos` collection through on-demand live queries (`components/subscription-timeline.tsx`): the subscribed channels are cut into slices of at most 40 ids, each slice pages 36 videos at a time (`useLiveInfiniteQuery`, newest first), and `lib/timeline-merge.ts` merges the slices, showing only what no unloaded page could precede; the next pages load when the end of the grid scrolls into view (`VirtualGrid` `onEndReached`). Its count appears once every page is loaded. One `POST /api/subscriptions/refresh` per profile and subscription set updates expired channel listings in the background (four at a time); cached videos show immediately and the first page reloads only if something was refreshed. Typed searches use a substring filter on the titles (and the names of the subscribed channels), so they ignore ASCII case but accents must match. `api.refreshSubscriptions` shares one in-flight request per profile, so the notification bell and this page never refresh twice at once; it is not cancellable, callers that go away ignore the answer.

`Notifications` (the bell) asks `GET /api/notifications` after that refresh, again on opening and every five minutes while the page is visible, and marks its list seen only when **Mark all as seen** is pressed; `ThemeToggle` (beside the bell) switches light and dark only; `lib/series-seasons.ts` splits a series into season blocks (only when every season is one uninterrupted run), and `CollapsibleCard` takes `actions` (beside the toggle), `className` and `scroll` so cards can share a fixed-height column and scroll their own body.

Full-page and quick search share a 400 ms debounce; Enter is immediate and pasted video links require explicit validation. Debounced navigation replaces the current history entry and retains platform/session context. Quick-search video rows and `VideoCard` share original-title selection, the four-request visible metadata queue and thumbnail-variant fallback. Listing titles stay visible until verified originals arrive, and the account preference remains authoritative. Twitch titles already verified by the provider do not show a title-verification error when unrelated metadata enrichment fails. `useLocalSearch` answers from records the server already caches before the live search does: a bounded, debounced title/name lookup in the `videos` and `channels` collections (never the whole cache), ranked with Fuse.js (`lib/local-search.ts`, pure and tested), narrowed by the search's platform intent. Local matches lead the quick-search dialog under a **Your library** heading and the full-page grid, and the server answers are appended de-duplicated. `useVideoStatuses` joins the active profile's watch history and reactions for the videos of a list only (in chunks of at most 40 ids, never one query over the whole history; `lib/video-status.ts` is the pure join) so results state known facts: cards show the watched overlay and badge, a liked heart and a resume-progress bar, and quick-search rows condense the same into chips beside the channel name (watched, liked, "resume at mm:ss"), all updating in real time. Subscription overflow reserves only the right-arrow gutter, keeping the first channel aligned. The topbar's icon buttons align to the top of the bar; chapter timecodes align with the title's first line.

The server links same-name channels of one creator on several platforms on its own (see the root README); `lib/channel-groups.ts` only reads the result. Linked subscriptions retain separate platform records and share a server-owned `creator` relation (`expand.creator` carries its name); they display one filter with platform badges and select both catalogs. A selected creator offers **Separate** (`POST /api/subscriptions/ungroup`, which clears the creator, deletes it and marks each member `ungrouped` so the server never links it again by itself); `ungroupedDuplicates` lists such separated pairs for an explicit **Group** action, which lifts the mark. The server deletes a creator as soon as fewer than two subscriptions share it. Account export/import carries each creator as a per-profile key and name.

`useSubscriptionsLive` asks `GET /api/subscriptions/live` once per profile and subscription set, then every two minutes while the page is visible. The Subscriptions page turns the answer into a red dot on the channel bubbles (`ChannelFilters` `live`) and live `VideoResult`s placed ahead of the loaded pages; `VideoCard` shows their **LIVE** badge and viewer count and skips metadata enrichment for them, and `VideoGrid` never treats them as watched.

Settings lives in the account popover, with vertical Account, Profiles, Appearance, Language and Playback tabs; `/admin` is administrator-only. The page footer links to `/licenses`. Account settings show email and password forms together. The top-left selector switches profiles and links to `/settings?tab=profiles` for creation, renaming, activation and deletion. Subscriptions, reactions, watch history, resume checkpoints and the local feed are scoped to the active profile. Hooks immediately filter out stale rows on switching, and the local feed and player remount with a profile key. `/api/feed?profile=<id>` requires an owned profile and cancelled requests cannot repopulate another profile's view. Deletion cascades to profile activity; the last profile cannot be deleted. Settings and connected sources stay account-wide. The sidebar toggle sits beside the page title in compact and expanded layouts. Pages use the available width. Translations use semantic keys from `src/providers/translations/en.ts`; `fr.ts` implements the same typed key set.

The shared brand uses `public/favicon.svg` in the sidebar and authentication pages. Account settings show the avatar and display name together; selecting the avatar opens the image picker, its corner button removes the image, and display-name changes save after a short pause. Profile management keeps its heading, actions and list in a shared settings card.

Appearance offers light, dark and system modes, stored locally on the device. The colour palette is not a device setting: it belongs to the active profile (ten palettes, teal by default) and subtly tints shared backgrounds, cards, navigation and borders, with a stronger accent for controls.

The profile switcher follows the sidebar navigation styling, with an open-state highlight and dropdown indicator instead of a bordered pill.

A profile record carries optional `icon` (a key of `PROFILE_ICONS` in `lib/profile-appearance.ts`) and `theme` (one of the accent palettes). `ProfileAvatar` renders the icon inside its own `data-accent` scope, so the switcher shows every profile in its colour; `ProfileTheme`, mounted inside `ProfilesProvider`, calls `ThemeProvider.setAccent` with the active profile's palette (or `DEFAULT_ACCENT` when it has none) once profiles are loaded. The last accent applied is kept in local storage only so a reload does not flash the default before profiles load. `ProfileDialog` (a native modal like the confirm dialog) creates and edits profiles; the settings list has no inline editing.

Settings → Profiles offers **Move subscriptions…** on each profile (`MoveSubscriptionsDialog`): a target profile (another one of the account, or a new one created inline with `createProfile(…, { select: false })` so the active profile does not change), the source profile's subscriptions as a searchable checklist (`lib/subscription-move.ts`: a creator group is one row selecting all its members), then `POST /api/subscriptions/move` `{from, to, subscriptionIds, copy?}`. The server does it in one transaction: a channel the target already follows is merged (the source row is dropped, never duplicated), a creator moves with its members when all of them move and the moved members leave it otherwise; notification markers, series and watch history stay with the source profile. The dialog reports moved/merged counts and refetches the subscriptions collection (realtime updates it too); closing it offers the undo snackbar, which moves the moved rows back and copies the merged ones back (`copy: true`).

The native administration page fetches fresh capabilities from `/api/account` rather than trusting cached user roles. It exposes server-paginated user management only after administrator access is confirmed. Go endpoints recheck roles inside serialized transactions, protect the last admin, and return whitelisted DTOs without credentials or source secrets. Initial promotion uses the explicit `viyu admin promote EMAIL --dir=...` CLI; public user APIs reject all role changes and modifiers.

`VideoControls` renders the player's timeline, volume, fullscreen and keyboard controls, plus the integrated quality/audio menu. `useHlsPlayback` uses hls.js with Go-proxied HLS resources and adds the Bearer header to those requests (`xhrSetup`/`fetchSetup`); a fatal media or network error is recovered once (`recoverMediaError`, `startLoad`) before the retry panel appears. Auto explicitly selects the highest available level; account quality limits are applied before loading segments. Audio defaults to the metadata's original language, independent of UI locale. Quality/audio changes do not replace the media element or reset playback position/state. Local watch-history records store the latest position and restore it after metadata and history load. Per-video/source component identity resets overrides for the next video. Fatal playback and metadata errors replace the controls with an in-player retry panel.

The player menu separates quality, audio and speed into panels. Focus moves to the checked option on entering a submenu and returns to its parent entry on Back/Left/Escape. Menu arrows do not trigger video seeking. Playback speed (0.25×–2×) writes `HTMLVideoElement.playbackRate`; `ratechange` synchronizes the displayed value. The controls retain the current rate when the same video's media version is replaced, while a new profile/video starts at normal speed.

`useSponsorSegments` requests only SponsorBlock `sponsor`/`skip` entries, validates their intervals, deduplicates them and leaves playback untouched on failure or HTTP 404. The player offers a contextual skip button or uses the saved `auto_skip_sponsors` preference. Attribution lives on `/licenses`. SponsorBlock receives the video ID, never the PocketBase token or connected-source cookies.

`usePlaybackCheckpoint` writes a per-user/profile/video local checkpoint, then the profile's one history row for the video through the `watch_history` collection (serialized saves; a unique-index refusal re-reads the row and updates it). The final `pagehide` save is an independent keepalive request that never waits behind an in-flight save. Watch time is added once per checkpoint as the not-yet-saved delta of the session and capped at the video's duration, so re-watching never double counts (`nextDurationWatched`). The newest local/server timestamp controls resume after reload; HMR cleanup preserves `resumeAt` before the HLS engine is replaced. Saving is disabled until history initialization and media metadata are ready, preventing stream-reset zeroes from overwriting a valid position.

A video is watched when its history row's `watched` flag is set: the playback checkpoint raises it once the position or the watch time crosses 90 % of the video's duration (`reachedWatched`, the only place that threshold exists) and never lowers it, and "Mark as watched" sets it without touching `duration_watched`; `useVisibleVideos` applies that and the other visibility settings to a list. Feed/subscription card menus create that flag without inventing duration or position; marking unwatched removes all matching history and the local resume checkpoint. History and series/detail views poll background work with abortable sequential requests, retaining prior content on errors and offering explicit retry. Local history pages by `watched_at` descending (`useLiveInfiniteQuery`; likes page by like date the same way). Its removal menu opens the confirmation dialog and deletes the profile's history row of the video, only after successful server deletion. Subscription channel filters are toggles without an All button; many channels use a contained horizontal scroller and arrow controls, while the sidebar chip uses active-profile subscription data.

The client never requests channel avatars or subscriber counts: `ChannelAvatar` only displays the URL it is given and falls back to a generic icon when it is missing or fails to load. The server owns channel profiles: a background worker fills cached channels that lack an avatar or a subscriber count (subscribed channels first, retrying a failed lookup only after six hours), search results reuse avatars already cached, and PocketBase's realtime updates of the `channels` collection deliver new ones. `useCommunityDislikes` requests Return YouTube Dislike only for missing YouTube counts, validates the video ID and nonnegative integer estimate, and never submits user reactions or credentials. Canonical counts win; errors/429 stay unknown and real zero remains valid. Approximation/source information is visible in the player and credits are on `/licenses`.

The Subscriptions videos tab offers an All / platform filter whenever the selected channels span several platforms (for example a creator linked on YouTube and Twitch). It is built from the selected channels rather than from loaded videos and narrows the channels the slices query. The player reads the channel avatar and subscriber count from the live `channels` collection instead of requesting the channel; the server fills both, and wakes its profile worker when a video or search reveals a channel it has not listed yet. Videos played through a connected source show no subscriber count, because that channel is not in the public cache.
